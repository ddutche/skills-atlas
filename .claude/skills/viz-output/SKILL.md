# Produce a visual deliverable

The hub's `knowledge/` and `playbook/` files are working documents, not something to hand
someone else directly. This skill converts their contents into something presentable.

## Workflow

### 1. Confirm the deliverable and audience

Ask, if not already clear: what kind of output (diagram, one-pager, slide, document) and who
it's for. The framing changes based on whether this is for the user's own reference, a
prospect, or a client.

### 2. Pull the source content

Gather the relevant `knowledge/` and/or `playbook/` entries. Do not invent content not already
backed by an entry; if a gap exists, say so rather than filling it with a plausible-sounding
guess.

### 3. Build the deliverable

Use whatever format fits: an HTML/SVG diagram, a Markdown one-pager, or a slide outline. Favor
tools already available for the output type (e.g. the Artifact tool for a shareable rendered
page, a document skill if the requested format is Word/PowerPoint).

### 4. Save and confirm

Save the result under `visuals/`, named descriptively with a date, and tell the user exactly
what was produced, from which source entries, and where it landed.

## Discipline

- Never fabricate a statistic, quote, or claim not already present in a `knowledge/` or
  `playbook/` entry. If the deliverable needs something not yet in the hub, flag it and suggest
  a `research-refresh` pass first.
- Keep the deliverable's claims traceable back to the entries that produced them.
